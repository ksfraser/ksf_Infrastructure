## The rule being applied

`ksfraser` stays **lowercase**. PSR-4 governs the namespace->directory
mapping and says nothing about casing; PSR-1/PSR-12 ask for StudlyCaps, but
Composer's own spec requires a lowercase vendor name and PSR-4 defers to it.
Capitalising to `Ksfraser` would break interop with `ksfraser/staging-dto`,
`ksfraser/ksf-common-db` and the rest of the Packagist set. Every real-world
package (`symfony\`, `monolog\`) does the same thing.

- `ksf_FA_<Module>` -> `ksfraser\FrontAccounting\<Module>\`
- `ksf_<Module>`     -> `ksfraser\<Module>\`

## Guard rails

Several modules now carry a `ModuleConventionsTest` that fails the build on
vendor casing, namespace/directory mismatch, a hardcoded `0_` runtime table
prefix, or PHP-7.4-only syntax against a 7.3 floor. Copy one into any module
you migrate:

- `ksf_FA_SerialNumber/tests/Unit/ModuleConventionsTest.php`
- `ksf_fa_warehouse/tests/Unit/ModuleConventionsTest.php`

Watch for two traps the guard tests themselves fell into:

1. A `token_get_all` comment-stripper with a stray `continue` drops every
   `T_STRING` token, so the regex never sees a function name and the guard
   passes everything vacuously. Emit `$token[1]` for non-comment tokens.
2. A guard that greps raw file text will match its own explanatory comment.
